# Адаптация инсталлятора и скриптов под новую архитектуру CloudPosBridge

## Выполненные изменения

### 1. CloudPosBridge_Installer.iss
**ДО (старая структура):**
```
C:\CloudPosBridgePHP\
├── app\
│   ├── *.php (все файлы в одной папке)
│   ├── bank\
│   ├── templates\
│   ├── settings_storage\
│   └── logs\
└── php\, nssm\, drivers\
```

**ПОСЛЕ (новая архитектура):**
```
C:\CloudPosBridgePHP\
├── src\                    # бизнес-логика, адаптеры, контроллеры
├── public\                 # точка входа для Web/API
├── config\                 # только конфиги
├── bank\                   # только Go-бинарь и temp-файлы
├── scripts\                # только служебные скрипты
├── vendor\                 # только PHP-зависимости
├── logs\                   # централизованные логи
├── templates\, resource\, samples\
└── php\, nssm\, drivers\
```

**Ключевые изменения:**
- ✅ Чистое разделение по слоям (src, public, config, bank, scripts, vendor)
- ✅ Конфиги не перезаписываются при обновлении (`onlyifdoesntexist`)
- ✅ Служба настроена на `{app}\public` как рабочую директорию
- ✅ Логи направляются в `{app}\logs\`
- ✅ Ярлыки указывают на правильные пути
- ✅ Go-программа запускается из `{app}\bank\`

### 2. scripts/update_service.ps1
**Основные улучшения:**
- ✅ **Новая структура папок**: копирует в правильные места согласно архитектуре

- ✅ **Логирование**: все действия записываются в `logs/update_service.log`
- ✅ **Валидация структуры**: проверяет корректность после обновления

**Процесс обновления:**

3. Проверка критических файлов и папок

5. Валидация структуры

## Соответствие ТЗ

### ✅ Основные требования выполнены:
1. **Не смешиваются слои** - каждая папка содержит только свою часть кода
2. **Конфиги пользователя сохраняются** - при обновлении не перезаписываются
3. **Legacy-код не затрагивается** - `src/legacy` копируется как часть `src`
4. **Правильные точки входа** - служба работает из `public/`, Go-программа из `bank/`

### ✅ Структура проекта соответствует требованиям:
```
C:\CloudPosBridgePHP\
├── src\             # ✅ бизнес-логика, адаптеры, контроллеры
├── public\          # ✅ точка входа для Web/API
├── config\          # ✅ только конфиги
├── bank\            # ✅ только Go-бинарь и его temp-файлы
├── scripts\         # ✅ только служебные скрипты
├── vendor\          # ✅ только PHP-зависимости
└── logs\            # ✅ централизованные логи
```

### ✅ Ярлыки и запуск службы настроены правильно:
- **Web-интерфейс**: `http://localhost:8000/` (единая точка входа)
- **Служба Windows**: рабочая директория `{app}\public`, запуск `index.php`
- **Go-бинарь**: задание планировщика на `{app}\bank\mainbeznal.exe`

### ✅ Обработка конфигов и логов:
- Не перезаписываем существующий `settings.json`
- Все логи в `{app}\logs`
- Временные файлы Go-программы в `{app}\bank\temp`

### ✅ Скрипты обновления:
- Используют правильные пути новой структуры
- Логируют все шаги в `logs/update_service.log`
- Проверяют корректность после обновления
- Сохраняют пользовательские данные

## Инструкции по тестированию

## DevOps-преимущества

- **Предсказуемость**: всегда одинаковая структура установки/обновления
- **Безопасность**: код не в public, конфиги не теряются
- **Масштабируемость**: легко добавлять новые компоненты
- **Отладка**: централизованные логи, детальная диагностика
- **Автоматизация**: готовность к CI/CD и Docker
