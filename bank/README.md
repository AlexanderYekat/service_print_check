# Интеграция банковского терминала

## Обзор

Реализована интеграция с банковским терминалом по чистой архитектуре через Go-программу. Все взаимодействие происходит через временные файлы, что исключает прямое использование COM-объектов в PHP.

## Архитектура

### Компоненты

1. **Go-программа** (`mainbeznal.exe`)
   - Обеспечивает работу с COM-объектом банковского терминала
   - Получает параметры через временные файлы
   - Возвращает результат в формате JSON

2. **PHP Адаптер** (`GoBankTerminalAdapter`)
   - Инкапсулирует логику взаимодействия с Go-программой
   - Реализует интерфейс `BankTerminalInterface`
   - Обрабатывает ошибки и таймауты

3. **UseCase** (`ProcessBankPaymentUseCase`)
   - Содержит бизнес-логику банковских операций
   - Валидирует входные данные
   - Обрабатывает результаты операций

4. **Контроллер** (`BankPaymentController`)
   - Обрабатывает HTTP-запросы
   - Поддерживает legacy API
   - Форматирует ответы

## Поддерживаемые операции

- **pay** - Оплата по банковской карте
- **refund** - Возврат денежных средств  
- **cancel** - Отмена операции
- **close_shift** - Закрытие смены терминала

## Конфигурация

В `config/settings.json`:

```json
{
  "bank": {
    "binary_path": "./bank/mainbeznal.exe",
    "timeout": 30,
    "emulation": false
  }
}
```

## Формат обмена данными

### Входные файлы:
- `temp/operation.txt` - тип операции
- `temp/amount.txt` - сумма в копейках (для денежных операций)

### Выходной файл:
- `temp/result.json` - результат операции

```json
{
  "Success": true,
  "Message": "Операция успешно выполнена",
  "Cheque": "слип банковского терминала",
  "CodeReturn": 0
}
```

## Тестирование

Включен режим эмуляции для тестирования без реального терминала:

```json
{
  "bank": {
    "emulation": true
  }
}
```

## Legacy файлы

Старые файлы перенесены в `src/legacy/`:
- `bankutils.php` - оригинальный драйвер через COM
- `bank-operation.php` - операции через PowerShell

## Сборка Go-программы

```bash
go build -o mainbeznal.exe mainbeznal.go beznal.go
```

## Преимущества

1. **Чистая архитектура** - разделение ответственности между слоями
2. **Тестируемость** - возможность unit-тестирования всех компонентов
3. **Надежность** - обработка ошибок и таймаутов
4. **Совместимость** - поддержка legacy API
5. **Производительность** - изоляция COM-логики в Go-программе
