# 🧪 Тесты бизнес-логики для получения веса и проверки марки

## 📋 Обзор

Созданы комплексные unit-тесты для всех ключевых компонентов бизнес-логики:

- **Получение веса** - `GetWeightUseCase`
- **Проверка марки (permit)** - `PermitMarkCheckUseCase`
- **Проверка марки (ecr)** - `EcrMarkCheckUseCase`
- **Доменная модель кода маркировки** - `MarkingCode`
- **Реестр проверок** - `MarkCheckRegistry`

**Итоговая статистика:** `57 тестов` в `5 компонентах` ✅

---

## 🏗️ Архитектура тестов

### **Принципы тестирования:**
- **Unit-тесты** - изолированное тестирование бизнес-логики
- **Mock-объекты** - эмуляция внешних зависимостей
- **Все сценарии** - успешные, неуспешные и граничные случаи
- **Чистая архитектура** - тесты не зависят от инфраструктуры

### **Структура:**
```
tests/unit/domain/
├── GetWeightUseCaseTest.php        (7 тестов)

├── MarkCheckRegistryTest.php       (10 тестов)
└── DomainTestRunner.php            (запуск всех тестов)
```

### ⚡ **EcrMarkCheckUseCaseTest** (8 тестов)

**Цель:** Тестирование асинхронной проверки марки на ККТ

**Сценарии:**
- 📤 Постановка задачи в очередь
- ✅ Получение успешного результата
- ⏳ Статус незавершенной задачи (PENDING)
- ❌ Неуспешный результат задачи
- 🔍 Несуществующий taskId
- 🗂️ Управление taskMapping (связка taskId ↔ код + контекст)
- 💾 Прямое сохранение результата
- 📦 Контекст с ИНН и GTIN

**Ключевые особенности:**
- Управление жизненным циклом задач
- Сохранение только успешных результатов в реестр
- Автоматическая очистка taskMapping после получения результата

**Mock-классы:**
```php
MockSuccessfulEcrGateway     // Успешная обработка
MockPendingEcrGateway        // Незавершенные задачи
MockFailedEcrGateway         // Неуспешные результаты
MockUnknownTaskEcrGateway    // Неизвестные taskId
MockContextAwareEcrGateway   // Проверка контекста
```
