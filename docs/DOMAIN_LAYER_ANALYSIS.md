## 🎯 Что такое доменный слой?

**Доменный слой** — это ядро приложения, которое содержит:

### ✅ Что ДОЛЖНО быть в доменном слое:
- **Бизнес-логика** — правила предметной области
- **Доменные модели** — сущности со своим поведением
- **Инварианты** — защита от некорректных состояний
- **Use-cases** — сценарии использования системы

### ❌ Чего НЕ должно быть в доменном слое:
- HTTP запросы/ответы
- Работа с базой данных  
- Логика валидации API
- Знание о файловой системе
- Форматирование для UI

## 🚫 Стандартные ошибки

### 1. **"Всё знать сразу"**
```php
// ❌ Плохо - требует результат в конструкторе
$transaction = new BankTransaction('pay', 1000, true, null, null, 'slip');
```

### 2. **"Доменная модель знает об инфраструктуре"**
```php
// ❌ Плохо
class BankTransaction {
    public function saveToDatabase() { /* ... */ }  // Знание о БД
    public function sendHttpRequest() { /* ... */ } // Знание о HTTP
}
```

### 3. **"Отсутствие инвариантов"**
```php
// ❌ Плохо - можно создать некорректное состояние
$transaction = new BankTransaction();
$transaction->setAmount(-1000); // Отрицательная сумма!
```

## 🏗️ Два подхода к моделированию

### 📌 Подход 1: "Факт свершившейся операции"

**Текущий в проекте** — модель создается только после получения результата от терминала.

```php
// ✅ Плюсы:
// - Всегда полная и валидная
// - Представляет завершенную операцию
// - Простая логика

// ❌ Минусы:  
// - Нет промежуточных состояний
// - Сложно отследить процесс
```

### 📌 Подход 2: "Эволюция состояния"

**Рекомендуемый** — модель может находиться в незавершенном состоянии.

```php
// 1. Создание в "ожидающем" состоянии
$transaction = BankTransaction::createPayment(1000.00);
echo $transaction->isPending(); // true

// 2. Обновление результатом
$transaction->setSuccessResult($slip);
echo $transaction->isSuccessful(); // true
```

**Преимущества:**
- Отслеживание жизненного цикла
- Ясное разделение ответственности
- Лучшее логирование и мониторинг
- Возможность отмены операций

## 🎯 Правильная архитектура слоев

```
┌─────────────────────┐
│   API Controller    │ ← Валидация запросов, форматирование ответов
├─────────────────────┤
│     Use Case        │ ← Сценарии, координация, логирование  
├─────────────────────┤
│   Domain Model      │ ← Бизнес-логика, инварианты
├─────────────────────┤
│   Infrastructure    │ ← Банковский терминал, БД, HTTP
└─────────────────────┘
```

### Поток данных:
1. **Controller** получает HTTP запрос → валидирует → вызывает Use Case
2. **Use Case** создает доменную модель → обращается к инфраструктуре → обновляет модель
3. **Domain Model** содержит бизнес-логику и защищает инварианты
4. **Infrastructure** выполняет технические операции

---

## 📊 Сравнение подходов

| Аспект | Текущий подход | Улучшенный подход |
|--------|---------------|-------------------|
| **Создание модели** | После получения результата | До выполнения операции |
| **Состояния** | Только "завершено" | "Ожидает" → "Завершено" |
| **Отслеживание** | Сложно | Легко |
| **Тестирование** | Сложнее | Проще |
| **Логирование** | Ограниченное | Полное |
| **Отмена операций** | Сложно | Естественно |

## 🧪 Тестирование доменного слоя

### Unit-тесты доменной модели:
```php
public function testTransactionLifecycle() {
    // Создание
    $transaction = BankTransaction::createPayment(1000.00);
    $this->assertTrue($transaction->isPending());
    
    // Успешное завершение
    $transaction->setSuccessResult('SLIP_123');
    $this->assertTrue($transaction->isSuccessful());
    $this->assertFalse($transaction->isPending());
    
    // Повторное изменение запрещено
    $this->expectException(LogicException::class);
    $transaction->setSuccessResult('ANOTHER_SLIP');
}
```

### Integration-тесты Use Case:
```php
public function testPaymentUseCase() {
    $mockTerminal = new MockBankTerminal();
    $useCase = new ProcessBankPaymentUseCase($mockTerminal, $logger);
    
    $transaction = $useCase->pay(1000.00);
    
    $this->assertInstanceOf(BankTransaction::class, $transaction);
    $this->assertTrue($transaction->isCompleted());
}
```

## 🎯 Заключение

**Доменный слой** — это сердце приложения. Правильно спроектированный доменный слой:

1. **Выражает бизнес-логику** понятным языком
2. **Защищает от ошибок** через инварианты  
3. **Не зависит от внешних систем**
4. **Легко тестируется** и расширяется

Ваш текущий подход уже достаточно хорош, но подход с "эволюцией состояния" даст больше гибкости для будущего развития системы.
