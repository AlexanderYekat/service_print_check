# Рефакторинг доменной модели чека - ЗАВЕРШЕН

## Обзор изменений

Выполнен полный рефакторинг доменной модели чека в соответствии с принципами чистой архитектуры и строгой типизации.

## Что было изменено

### До рефакторинга
```php
class Check {
    public array $tableData;   // [{name, quantity, price}, ...]
    public array $payments;    // [{type, amount}, ...]
    // ...
}
```

### После рефакторинга
```php
class Check {
    /** @var CheckItem[] */
    private array $items;
    
    /** @var Payment[] */
    private array $payments;
    
    // Строгая типизация + бизнес-логика
}
```

## Новые классы

### 1. CheckItem
**Назначение**: Элемент чека с строгой типизацией
**Поля**:
- `name: string` - наименование товара
- `price: float` - цена за единицу
- `quantity: int` - количество
- `sum: float` - сумма за позицию
- `markingCode: MarkingCode|null` - код маркировки

**Бизнес-методы**:
- `isSumCorrect()` - проверка корректности суммы
- `calculateCorrectSum()` - расчет правильной суммы
- `hasMarkingCode()` - проверка наличия маркировки
- `toArray()` - сериализация для API

### 2. Payment
**Назначение**: Платеж в чеке с типизацией
**Поля**:
- `type: string` - тип платежа ('cash', 'card', 'other', ...)
- `amount: float` - сумма платежа

**Бизнес-методы**:
- `isCash()`, `isCard()`, `isElectronic()` - проверки типа
- Статические конструкторы: `Payment::cash()`, `Payment::card()`
- `toArray()` - сериализация для API

### 3. Check (переработанный)
**Назначение**: Основная доменная модель чека
**Поля**:
- `items: CheckItem[]` - массив позиций (строго типизирован)
- `payments: Payment[]` - массив платежей (строго типизирован)
- `cashier: string` - кассир
- `type: string` - тип чека
- `taxationSystem: string` - система налогообложения

**Бизнес-методы**:
- `getTotalAmount()` - общая сумма товаров
- `getTotalPayments()` - общая сумма платежей
- `isPaymentBalanced()` - проверка баланса платежей
- `getMarkedItems()` - получение маркированных товаров
- `getCashAmount()`, `getElectronicAmount()` - суммы по типам платежей
- `areAllItemSumsCorrect()` - валидация всех сумм
- `toArray()` - сериализация для API
- `fromArray()` - создание из массива (обратная совместимость)

## Ключевые принципы

### ✅ Выполнено согласно ТЗ

1. **Нет массивов внутри моделей** - только строго типизированные объекты
2. **Вся бизнес-логика в доменных классах** - расчеты, валидация, проверки
3. **Сериализация только для API-слоя** - методы `toArray()` для DTO
4. **Использование MarkingCode** - интеграция с существующим value-object
5. **Полная валидация входных данных** - типы, диапазоны значений
6. **Обратная совместимость** - метод `fromArray()` для API

### Преимущества новой структуры

#### Для разработки:
- **Типобезопасность** - IDE автодополнение, статический анализ
- **Тестируемость** - четкие интерфейсы, нет внешних зависимостей
- **Расширяемость** - легко добавлять новые бизнес-методы
- **Читаемость** - понятная структура, самодокументируемый код

#### Для бизнеса:
- **Надежность** - валидация на уровне домена
- **Точность расчетов** - встроенные методы расчета сумм
- **Работа с маркировкой** - встроенная поддержка кодов маркировки
- **Гибкость платежей** - поддержка разных типов оплаты

## Примеры использования

### Создание чека (новый способ)
```php
// Создаем позиции
$items = [];
$items[] = new CheckItem('Хлеб', 45.50, 2, 91.00);
$items[] = new CheckItem(
    'Молоко', 
    89.90, 
    1, 
    89.90, 
    new MarkingCode('012345678901234567890123456789')
);

// Создаем платежи
$payments = [];
$payments[] = Payment::cash(100.00);
$payments[] = Payment::card(80.90);

// Создаем чек
$check = new Check(
    $items, 
    $payments, 
    'Иванов И.И.', 
    Check::TYPE_SELL, 
    'osn'
);

// Бизнес-логика
echo $check->getTotalAmount();        // 180.90
echo $check->isPaymentBalanced();     // true
echo count($check->getMarkedItems()); // 1
```

### Обратная совместимость (из массива)
```php
$legacyData = [
    'tableData' => [
        [
            'name' => 'Товар',
            'price' => 100.0,
            'quantity' => 1,
            'sum' => 100.0,
            'marking_code' => 'код_маркировки'
        ]
    ],
    'payments' => [
        ['type' => 'cash', 'amount' => 100.0]
    ],
    'cashier' => 'Петров П.П.',
    'type' => 'sell',
    'taxationSystem' => 'osn'
];

$check = Check::fromArray($legacyData);
// Далее работаем как с обычным объектом Check
```

### Валидация и бизнес-правила
```php
// Автоматическая валидация при создании
try {
    $item = new CheckItem('', -10, 0, -5); // Выбросит исключения
} catch (InvalidArgumentException $e) {
    echo $e->getMessage(); // "Наименование товара не может быть пустым"
}

// Бизнес-проверки
if (!$check->areAllItemSumsCorrect()) {
    // Есть ошибки в расчетах
    foreach ($check->getItems() as $item) {
        if (!$item->isSumCorrect()) {
            echo "Ошибка в позиции: " . $item->getName();
            echo "Должно быть: " . $item->calculateCorrectSum();
        }
    }
}
```

## Совместимость с API

Новая модель полностью совместима с существующим API через методы:
- `Check::fromArray()` - создание из JSON/массива
- `Check::toArray()` - преобразование в массив для JSON
- Сохранены все ключи: `tableData`, `payments`, `cashier`, `type`, `taxationSystem`
