# План внедрения поддержки маркированных товаров

## 1. Моделирование данных
- [x] Добавить в модель позиции чека поле `mark_code`.
- [x] Ввести уникальный идентификатор для каждой позиции (например, `position_id`).

## 2. Добавление позиции в чек
- [ ] При добавлении маркированной позиции сохранять её с уникальным ID и маркой.
- [ ] Сначала отправлять марку на localhost API для "разрешительного режима" и сохранять результат.
- [ ] Возвращать результат проверки из "разрешительного режима" внешней программе сразу при регистрации позиции.
- [ ] Для маркированных позиций инициировать процесс проверки марки на ККТ (асинхронно).
- [ ] Сохранять статус проверки марки на ККТ ("ожидание").

## 3. Асинхронная проверка марки на ККТ
- [ ] Реализовать опрос статуса проверки марки по ID/марке.
- [ ] Обновлять статус проверки у соответствующей позиции.

## 4. Пробитие чека
- [ ] При формировании чека собирать все позиции, включая маркированные.
- [ ] Для каждой маркированной позиции прикладывать результат проверки марки на ККТ.
- [ ] Отправлять чек с результатами проверок в ККТ.

## 5. Синхронизация и обработка ошибок
- [ ] Обеспечить связь между позицией в чеке и процессом проверки через `position_id`.
- [ ] Обрабатывать ситуации, когда проверка марки на ККТ не завершена к моменту пробития чека (например, ожидание или ошибка).

## 6. Тестирование (пока не надо)
- [ ] Покрыть тестами сценарии с маркированными и немаркированными позициями.
- [ ] Проверить корректность синхронизации статусов и результатов проверок.
